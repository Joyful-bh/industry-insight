# 输入与结果契约

## 企业名单

输入为 `.xlsx`，默认第一张工作表；指定其他表时使用 `--sheet`。必须包含表头 `企业名称`、`统一社会信用代码`。代码单元格可为空，此时沿用原程序的源行号标识；必须检查重复企业标识。空表或缺少表头不能直接进入 API 调用。

可选但影响判断的字段：`主行业`、`国标行业领域`、`经营范围`、`企业简介`、`经营状态`、`省份`、`城市`、`区县`。缺失允许为空，不由 Agent 编造补齐。生产程序处理工商模板简介、非活跃企业与数据质量标记。

用户输入文件保持不变；新 Excel 追加候选状态、最终标签、确认匹配、较可能匹配、待确认赛道、补充档案状态、数量和判断依据等字段。保留原工作簿的其他工作表与已有格式。

## 赛道定义

支持 JSON 数组、`{"tracks": [...]}` JSON 对象，或每行一个赛道的 JSONL。至少明确以下字段：

- `track_id`：唯一、稳定的赛道标识。
- `name`、`definition`：名称及定义边界。
- `core_products_services`、`included_activities`、`excluded_activities`、`observable_company_features`：字符串数组。
- 可选：`aliases`、`positive_terms`、`negative_terms`、`enterprise_archetype`。

这些输入边界控制生产判断，不把“更适合另一个赛道”作为排除当前赛道的理由。接受多赛道标签。

Skill 不含开发者的权威赛道快照。用户提供指定版本的赛道文件；同一次续跑继续使用同一版本。其他 Skill 输出的赛道或 HTML 看板不能未经检查就当作 classification-ready 输入。

## 按需辅助工具

`runtime/scripts/tracks/` 保留原项目的看板提取、赛道审计与整理、SMB 映射和赛道看板生成工具。只有用户要求整理赛道或输入需要转换时使用；必须显式传入用户输入、输出和目录参数，不使用开发者历史数据位置。SMB 映射工具还需要用户提供产品服务目录。企业归类不自动执行这些步骤。

“未进入候选召回”“证据不足仍待确认”“已核验不匹配”是不同结果，不能合并成“不属于任何赛道”。候选预算是全局企业—赛道对预算，不是每企业配额。
