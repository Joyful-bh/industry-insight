# 企业赛道归类

程序执行完整生产链路；Agent 获取输入、引导配置百炼 Key、监督运行、处理异常并交付结果。必须保留 BM25 与 E0_WEIGHTED 召回、批量本地核验、未决企业联网补档及 Excel 导出规则，不用 Agent 自行判断替代 API 阶段。

## 获取输入与环境

1. 获取企业 `.xlsx` 和 classification-ready 赛道 `.json` / `.jsonl`，以及必要的工作表名称。阅读 [references/inputs.md](references/inputs.md) 检查文件。没有赛道输入时向用户索取，不能凭模型记忆补造赛道。
2. 选定用户工作目录，读取 [references/setup-and-api-key.md](references/setup-and-api-key.md) 并初始化。目录可包含空格或中文。脚本路径根据当前已安装 Skill 的位置计算；业务代码、依赖、配置、缓存和产物不依赖开发者工作区。
3. 缺少 Key 时，先向用户解释向量、核验和补档需要阿里云百炼 API，再提供官方 Key 获取页面，指导登录、选择匹配的地域与业务空间、创建并复制可用于这些 API 的 Key。用户可将 Key 发到对话，由 Agent 经标准输入代为写入工作目录 `.env`；禁止复述 Key、放入命令参数、日志、报告或分发包。配置后只报告成功或失败。

## 完整运行与交付

阅读 [references/workflow.md](references/workflow.md)。依赖就绪、输入检查及网络预检通过后，说明真实调用会消耗百炼额度且企业分类材料会提交给模型服务，再运行统一入口。已明确要求运行的用户无需重复确认；高级搜索只在用户明确要求时开启。

链路为：企业准备、赛道准备、语义向量与缓存、固定混合召回、本地证据批量核验、初级联网补档与复判、可选高级搜索、Excel 导出。

中断后从同一工作目录 `resume`，由生产程序复用有效缓存；不要删除缓存、跳过未完成阶段或默认强制重调模型。异常时按需阅读 [references/troubleshooting.md](references/troubleshooting.md)。

交付生成的 Excel，报告企业数、取得标签的企业数、未决或未进入召回的数量及主要覆盖缺口。未取得标签不等于确认企业不属于任何赛道。保留用户原工作簿与已有格式；输入文件不能被输出覆盖。

## 范围

- 默认参数沿用正式项目：并发 8，候选预算 2000，核心预算 1600；扩大或缩小范围通过参数调整，算法与判断边界保持一致。
- 向量缓存使用本地 SQLite，其他中间结果使用文件，不需要 Docker 或数据库服务。
- 主交付是企业标签 Excel；赛道整理及赛道看板工具是按需辅助步骤，见输入说明，不自动重做赛道整理。
- 不随包携带企业数据、Key、真实向量缓存或历史运行结果。
