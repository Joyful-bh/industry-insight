# 核心/辅助 Topic 与分批归并回归结果

## 结论

核心 Topic、辅助 Topic 和排除项的分工值得保留。它使赛道身份只由直接证明产品和供给角色的材料定义，政策支持、产业热度和示范应用只提供背景；同时，完整输入核算消除了模型静默漏掉 Topic 或局部 Track 的风险。

强制分批实验也已经真实跑通，但没有证明略粗业务粒度可以仅靠归并提示词稳定泛化。259 个冻结 Topic 被拆为 9 批，局部阶段生成 67 条候选，当时的最终归并仍输出 67 条且未排除任何局部候选。该无效归并现已从正式回退链路删除。

因此，两项优先改进解决了“身份材料混杂”和“分批运行不可靠”，但没有解决最终目录的粗粒度一致性。当前结果可作为后续归并输入，不能直接作为全国正式赛道目录。

## 实现结果

正式链路现采用以下最小结构：

- `refs`：直接定义产品市场和供给角色的核心 Topic；
- `supporting_refs`：只说明政策支持、热度、示范应用或区域布局的 Topic；
- `excluded_refs`：不能构成目标制造企业赛道、也不能作为已有赛道辅助信号的 Topic；
- 每个输入 Topic 在局部生成中必须恰好出现一次；
- 核心 Topic 不能重复定义多条赛道，核心与辅助引用不能重叠；
- 定义仅由核心 Topic 生成，事件与区域统计可以使用核心和辅助 Topic。

当前处理器版本为 `topic-track-v17-no-model-merge`。正式回退链路只合并完全相同的 `offering_family + supplier_role`，不再调用模型进行跨批全局归并。正式流程仍由 `python -m track_insight pipeline-run` 运行。

## 有效改善

### 输入处理可审计

早期回归允许模型省略输入，无法区分“有意排除”和“忘记输出”。现在 259 个 Topic 均有唯一去向，67 个局部 Track 也均有唯一去向；重复引用和漏引用会直接导致契约失败，而不是生成看似完整的结果。

### 身份与背景得到分离

例如“6G 卫星载荷制造”由载荷生产线直接定义，6G 通信技术研发只作为辅助；“新能源汽车整车制造”由整车制造与交付材料定义，购置补贴和充电设施建设只作为辅助。此前会污染企业边界的宽泛产业、补贴和示范信号不再默认成为核心身份。

### 已知范围误判有所减少

单次全局校准版中的“氢能装备制造”“显示制造大模型”和“智能眼镜产业创新平台”未进入本轮结果，说明核心身份约束能够拦截一部分由应用、内部能力或平台材料推导出的伪制造赛道。

## 仍然存在的关键问题

### 最终归并实际失效

最终模型接收 67 个局部 Track，返回 67 个结果、0 个排除项。提示词虽规定父子重叠检查和反事实粒度检验，但模型采取了保守的“一项一留”策略。以下目录同时存在：

- AMOLED 显示面板、OLED 显示面板、MLED 显示产品、新型显示器件、显示面板与模组；
- 动力电池与储能电池、固态电池；
- 新能源汽车整车、智能电动汽车整车、L3 自动驾驶汽车、L4 自动驾驶量产车辆；
- 具身智能机器人、机器人本体与核心零部件；
- AI 芯片、应用处理器、系统级芯片、集成电路设计等父子或相邻设计市场。

单 Topic 赛道由 v4 的 40 条增加到 48 条，说明分批会放大局部命名差异；如果跨批归并不真正生效，全国规模下碎片会继续累积。

### 核心/辅助分类并不等于事实判断正确

“风电整机制造”仅由“先进能源产业”这一宽泛 Topic 形成；“LCD 电视显示技术”被赋予制造角色；“DRAM 存储芯片设计制造”把芯片设计与批量生产材料放在 `DESIGN_PRODUCT` 下；L4 车辆材料同时包含制造和运营。结构契约只能保证引用完整，不能替代语义正确性。

### 单次大归并任务负担过重

最终调用同时承担证据复核、范围排除、供给角色校验、父子消歧、粒度统一和重命名。输入很长，且“有疑问则保留”的安全规则与“必须消除父子重复”存在行为张力。小模型倾向于避免错误合并，结果就是不合并。

## 略粗粒度实验结论

不应继续向生成提示词追加行业示例，也不应建立人工穷举赛道注册表。实验过的动态平面业务市场层采用以下结构：

1. 局部阶段继续只做范围判断、供给角色和核心/辅助/排除核算，不要求一次确定最终粒度；
2. 将局部 Track 压缩为 `名称 + 产品市场 + 供给角色 + 一句企业边界`，按供给角色分组；
3. 模型只根据本轮候选动态提出少量上位业务市场，不维护永久父子树，也不参考人工修订目录；
4. 另一次分批调用把每条局部 Track 恰好分配到一个动态业务市场或排除项；
5. 程序按分配结果确定性归并，再对每个市场做一次内部一致性审查；
6. 若某市场内无法形成大体重合的客户名单，拆回原候选；若父项与子项销售覆盖相同，只保留父项。

这个结构把“提出共同粒度”和“逐项归属判断”拆开，单次输出只需要短编号和一个决定，避免让小模型在一个超长响应中同时创造目录、核验证据并维护完整引用。业务市场由每轮全国候选动态生成，因此能接收新赛道；它是本轮数据的归并中间层，不是用人工结果拟合的固定分类树。

该层已经使用本轮 67 条局部 Track 完成三轮离线验收，结果见 `dynamic-market-normalization-experiment-results.md`。它能产生真实归并，但仍不能稳定阻止纵向过度合并和最终父子重叠，因此实验实现已移除，未进入正式流程。
