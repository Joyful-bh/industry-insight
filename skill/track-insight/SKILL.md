# 赛道洞察

把用户输入转换为可追溯的赛道洞察和 HTML 看板。程序负责批量处理、SQLite 状态、校验、恢复和导出；Agent 负责澄清研究范围、配置凭证、启动与监督流程、处理异常并交付结果。

`runtime` 包含完整业务程序、默认配置和提示词，以及正式看板生成器和模板。API 模式执行正式 `pipeline-run` 的处理流程；Agent 演示将自身结果转换为正式看板的数据结构。Skill 通过自身所在位置定位程序，用户工作目录独立保存配置、Key、依赖、数据库和产物。

调用时以当前已安装 Skill 的目录为 `<Skill目录>`，以用户选定或当前任务目录为 `<工作目录>`。无须切换到 Skill 目录，命令采用 `python "<Skill目录>/scripts/run_pipeline.py" ... --workspace "<工作目录>"`。不要访问开发者原工作区或假定已有 Key 和历史数据库。

## 选择运行模式

- 正式研究默认使用百炼 API 模式。它支持完整流程和较大任务，要求 `DASHSCOPE_API_KEY`。
- 仅当用户没有 Key、明确要求演示或希望先看效果时，使用 Agent 原生模式。默认主动把范围收窄为单一区域、单一细分方向和少量代表性来源；除非用户明确要求扩大范围。该模式不适合大规模、长期、并发或无人值守任务，不得把演示结果表述成完整覆盖或趋势定论。
- 只支持阿里云百炼，不建议或配置其他搜索、模型提供方。

## 正式流程

1. 获取区域、行业和起止日期。缺少时提出最少的必要问题。
2. 在首次运行或环境异常时阅读 [references/setup-and-api-key.md](references/setup-and-api-key.md)，运行初始化和诊断。
3. 用户可直接在对话中提供 API Key。收到后不要复述、记录到回复或放入命令参数；启动 `scripts/configure.py ... set-key --stdin`，通过标准输入写入工作目录 `.env`，然后只报告配置成功或失败。
4. 阅读 [references/automated-workflow.md](references/automated-workflow.md)，先执行网络预检，再调用高层入口完成初始化、数据库建表、流水线运行和看板生成。若沙箱阻断外网，申请网络权限后重跑同一命令；不要把权限阻断消耗为页面重试。遇到业务阶段失败先查看状态并从已有计划恢复，不要无条件重跑成功阶段。
5. 交付看板路径、研究范围、关键数量、失败或覆盖缺口。结论必须可追溯到来源，不把搜索引用直接当成已核验事实。

## Agent 原生演示

阅读 [references/agent-native-demo.md](references/agent-native-demo.md)。先生成任务包，再由 Agent 使用自身可用的联网能力查找权威来源并形成结构化结果，最后交给脚本验证、写入 SQLite 并生成看板。若当前 Agent 没有联网能力，明确说明并请用户提供材料，禁止凭模型记忆编造来源。

## 不变量

- 不在消息、日志、命令行参数、结果文件或错误摘要中回显完整 API Key。
- 不要求 Docker 或 PostgreSQL；默认使用工作目录中的 SQLite。
- 自动化模式的每个工作包至少保留 4 个互补搜索任务；缩小实验预算时不得把 `max_searches_per_work_package` 调到 4 以下。
- 两种运行模式必须使用同一套正式离线看板模板；不得另写临时或极简 HTML 替代交付物。
- 原始事实、分析判断和业务建议保持可区分。
- 不伪造 URL、引文、发布日期或覆盖范围。
- 正式模式产生费用；开始真实批量调用前让用户知道将使用其百炼额度。
- 删除或覆盖已有工作目录、数据库、证据或报告前必须得到用户明确授权。

故障排查时按需阅读 [references/troubleshooting.md](references/troubleshooting.md)。
