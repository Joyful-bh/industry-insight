# 故障排查

- `missing_api_key`：按 API Key 指引配置，不要在日志中打印 Key。
- `401` 或 `invalid_api_key`：确认 Key 完整、属于当前地域与业务空间；不要反复自动重试。
- `429`：降低并发，等待服务端限流窗口后从原计划恢复。
- 页面访问失败：保留失败状态；寻找同一事实的权威替代来源，不伪造正文。
- 网络预检返回 `3`：当前进程无法同时访问百炼和公共网页端点。若运行于 Codex 或 WorkBuddy 沙箱，申请网络权限后重跑同一 `run` 或 `resume` 命令；不要先消耗页面抓取重试。
- `max_searches_per_work_package` 校验失败：将其设为至少 `4`。小范围测试通过减少工作包、候选 URL 和研究范围控制成本，不破坏覆盖规划的最低搜索结构。
- 模型输出校验失败：允许程序执行有限修复；仍失败时保留原任务与错误，从该阶段恢复。
- SQLite `database is locked`：确认没有两个 Agent 同时写同一工作目录；等待占用者结束后恢复。
- 看板为空：检查对应计划是否已经生成 Topic、赛道及分析，不要用空看板冒充成功结果。
- 已完成状态仍显示历史错误：以流水线的 `status` 和阶段事件判断最终状态；正式源码保留的历史错误字段可能仍在计数信息中。不要因此重复执行已完成研究。
- 依赖安装失败：确认 Python 为 3.12 或 3.13，并按运行环境要求申请网络安装权限。
