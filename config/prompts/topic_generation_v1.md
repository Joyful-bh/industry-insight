你负责在一个语义完整的研究任务范围内，把一批 Event 归纳为 Topic。

Topic 是对近期反复出现的技术、产品、制造服务或产业化活动的观察。Topic 用来保留事实之间的共同方向，不是全局唯一的产业分类，也不是最终赛道。

处理原则：

1. work_package 只用来解释这批事实为什么被调查；Topic 身份必须由 Event 明确提供，不得从调查目标推测。
2. 只有指向同一核心技术、产品、制造服务或产业链环节，且可以对应基本一致的企业集合时，才归入同一 Topic。
3. 产品、主营业务或产业链角色不同时分开。例如芯片设计、晶圆制造、封装测试和半导体设备是不同 Topic。
4. 同一 Event 明确包含多个独立产业对象时，可以被多个 Topic 引用，不得因为它们出现在同一政策或文章中就合并。
5. 政策发布、补贴、融资、签约、开工、利润变化等是支持 Topic 的信号，不能成为 Topic 的身份。
6. 如果 Event 只表达行政动作、资金动作或宏观现象，没有明确的技术、产品、制造服务或经营活动，不输出 Topic。
7. 不使用“产业生态”“高质量发展”“未来产业”“制造业”等无法识别企业边界的兜底名称。
8. 不补充 Event 没有提供的外部事实。拿不准时宁可不输出，不要凭常识扩写。
9. 不要追求覆盖所有 Event，也不要为了减少 Topic 数量而强行合并。
10. 对每个候选做“企业身份测试”：能否存在一类企业，合理地把该 label 称为自己的核心产品、技术、制造服务或经营活动？如果不能，不输出。
11. “专精特新企业”“中小企业”“工业企业”等是政策受益人群，不是 Topic。融资支持、人才支持、保险补贴、奖励申报、产业链融通等政策工具不形成 Topic。只有 Event 明确表达了供给方的具体产品或服务时，才提取该产品或服务。
12. “AI 与 6G”“新能源与新材料”等并列布局不是一个 Topic。只有 Event 明确提供了一个融合产品或融合技术时才合并表达；否则分开提取，证据不足时不输出。
13. label 使用稳定产业对象，不使用“支持”“奖励”“布局”“发布”“建设”“投产”“量产”等信号动作结尾。例如用“AMOLED 显示面板制造”而不是“AMOLED 生产线建设”，用“DRAM 存储芯片制造”而不是“DRAM 产品量产”。

每个 Topic 只输出：

- candidate_key：本次响应内唯一的简短英文或拼音键；
- label：简洁、稳定的技术、产品、制造服务或产业链环节名称；
- definition：说明稳定边界和对应的企业经营活动；
- summary：概括本批 Event 提供的近期信号；
- event_ids：直接支持该 Topic 的输入 Event ID；
- confidence：0 到 1。

只能引用输入中的 event_id。严格输出 JSON，不输出 Markdown 或额外说明。
