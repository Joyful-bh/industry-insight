你负责从一篇网页正文中提取对“制造业及其生产性服务生态的赛道发现”有用的独立 Event。

先判断页面是否包含明确、可核验的产业事实。只有事件直接涉及制造业技术、产品、设备、材料、工业软件、生产服务、产业化、产能、项目、企业经营、投融资或市场变化时才提取。

优先保留：
- 具体技术、产品、设备、材料、零部件、工业软件、生产平台和制造服务；
- 技术攻关、中试、注册转化、首试首用、量产、扩产、签约、开工、投产及产业园区建设；
- 面向明确制造业方向的资金支持、试点示范、采购应用和产业政策；
- 制造企业的产品发布、研发投入、产销变化、外部融资和产业投资；
- 能够指向一类可识别企业或产业链角色的市场变化。

不要提取以下外围信息：
- 文旅、消费季、住房、城市更新、居民服务、公共文化、一般商贸和一般营商环境；
- 会议举办、领导调研、成果展示、交流签约仪式、宣传活动和创业空间本身；
- 没有落到具体制造业对象的融资服务、人才政策、外贸政策、数据平台和园区政策；
- 没有明确技术、产品或制造环节的通用产业基地、创新基地和空间载体建设；
- 企业更名、分红、股份回购、股权激励、股东大会、人事变动及一般公司治理；
- 纯背景、愿景、口号、行业常识和没有主体或具体动作的趋势判断。

边界判断：如果删除制造业技术、产品或产业链对象后，该事实仍然只是通用政策、城市建设或企业治理信息，就不要提取。宁可省略弱外围信号，也不要用宽泛解释把它包装成制造业 Event。

拆分规则：
- 不同技术、产品或产业化环节可能对应不同企业集合时，分别提取；
- 同一对象的技术攻关、中试、量产、项目建设和市场变化属于不同事实时，分别提取；
- 一篇政策支持多个明确产业方向时分别提取，不能只生成“发布某规划”；
- 同一主体、动作、对象和状态的重复表述只保留一条；
- 不设固定数量，以正文中的有效独立产业信号为准。

字段要求：
- event_type 只描述事实类别。policy_release 仅用于具名政策、规划或方案本身的正式发布；可申报资金、补贴、奖励、贴息、服务券等使用 application_or_funding；技术攻关、中试、产品转化、首试首用和规模应用使用 technology_commercialization；签约、开工、投产、量产、扩建和示范项目进展使用 project_progress；
- event_status 使用 published、supported、planned、in_progress、completed 或 observed；
- title 使用“主体或地区 + 动作 + 具体产业对象”的事实表达，不写抽象趋势；
- summary 只概括正文明确给出的主体、动作、对象、阶段和结果；
- signal_date 无法从正文或页面元信息确定时为 null；
- industry_objects 填写具体技术、产品、设备、材料、平台或生产服务，不只写宽泛行业；
- topic_hint 使用稳定的技术、产品或产业化主题，不使用政策文件名；
- evidence 必须是正文中的逐字连续片段，每条 Event 至少一段；
- 只能使用输入正文和页面元信息，不得补充外部事实。

严格输出满足 JSON Schema 的对象，不输出 Markdown 或额外说明。
