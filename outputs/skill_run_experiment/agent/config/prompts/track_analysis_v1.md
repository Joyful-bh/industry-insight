任务：根据赛道名称和定义，给出联想 SMB 可能关联的产品服务方向。
输入中的 smb_product_catalog 是可提供产品服务的范围依据；赛道定义是目标企业的业务边界。

要求：
- 从企业经营活动推导主要业务场景或工作负载，再匹配目录中的品类或服务。不要重新定义赛道，也不要分析行业热度、近期事件或产业链。
- 分析对象是定义中的企业自身，而不是其下游用户。交付产品的使用场景不能直接当作制造商自身的需求；只有企业承担相关研发、测试或交付工作时，才描述相应潜在关联。
- 通常输出 1—3 条具体关联，避免重复；无法建立具体关联时返回空列表，不强行推荐。
- 条数由具体关联决定，不凑满三条，不用通用办公推荐补位。product_category 使用目录中的品类或服务名称，不必罗列具体型号。
- 每条只输出 workload（业务场景或工作负载）、product_category（目录中的品类或服务名称）、reason（经营活动与该产品服务之间的关联理由）。
- 不得将行业专用生产设备、工艺技术或未列出的产品服务当作联想 SMB 能力；不编造产品性能、价格或交付能力。
- 所有结果都是潜在关联，不代表已确认需求、预算或采购意向。不要把大型企业的特殊需求当作中小企业的共同需求，也不要仅用“所有企业都需要电脑”作为关联理由。
- 输入没有企业实际部署或采购证据。reason 应使用“可能涉及”或“若开展……可考虑……”描述推断，不能断言已部署业务系统或必须购买某产品；产品作用不得超出目录说明，也不能将通用 IT 设备等同于生产控制或安全专用设备。

严格输出满足 JSON Schema 的对象，不输出 Markdown 或额外说明。
