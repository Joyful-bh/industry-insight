你根据已经初步识别的制造业候选 Track，提出实际可以归并的共同业务市场和成员。

这个目录服务于联想 SMB 对 PC、工作站、服务器、存储等基础 IT 产品的客户覆盖。它不是产品百科、产业分类树或永久注册表，只用于将本轮明显过细的技术路线、代际和应用变体归到略粗但仍可识别客户的市场。

规则：

1. 每个市场必须在 member_refs 中列出至少两个真实输入 track_ref，且合并能减少重复或过细技术变体。独立方向不输出，程序自动保留。禁止为每条候选复制一个目录项。没有合理合并时 markets 为空。
2. 同一市场内的企业应具有大体重合的潜在客户名单、研发生产工作负载和销售覆盖方式。仅因都属于制造业或都使用通用 IT 设备不得合并。
3. 只合并同一可售产品层级上的横向变体：技术路线、代际、等级、能源形式、智能化程度、材料体系或单一应用不同，但最终交付物和供应企业群基本相同时，可以使用共同市场。
4. 产业链上下游或组合使用关系不是共同市场。整机与零部件、系统与子系统、设备与耗材、产品与生产设备、产品设计与直接制造工序不得放入同一目录项，即使它们服务同一终端行业。
5. 仅仅面向同一应用领域不代表交付物相同。一个目录项不能用宽泛行业名称包住药品、器械、材料、设备等不同交付物。
6. 不维护父子层级。不得同时提出一个宽泛父市场和它的技术路线、代际或应用子市场。若多个候选只是同一整机产品的动力、智能或技术配置差异，应只提出共同整机市场。
7. supplier_role 必须保持一致，不同角色永不进入同一市场。
直接生产服务还必须属于相同核心工序；同一产业链中的不同生产工序不是技术路线或应用变体。
8. 市场名称必须能直接描述制造企业主营产品或工业软件，不使用“产业、生态、项目、园区、平台建设”等宽泛表述。
9. 不依赖固定赛道清单，也不补充输入之外的产业方向。
10. market_ref 使用 M1、M2 等短编号，且不得重复。

11. 一个 track_ref 最多属于一个合并组；每个组必须完整覆盖所有成员定义，但不能把不同供给角色或不同最终交付物拼成宽泛大行业。共同市场与未合并项仍存在同层级横向重叠时，应重新考虑成员集合；不以删掉有效方向来减少数量。

每个实际合并组只输出 market_ref、name、offering_family、supplier_role、一句 boundary 和 member_refs。未归组候选不输出 KEEP 或 EXCLUDE，不承担来源有效性审核。只输出紧凑 JSON。
