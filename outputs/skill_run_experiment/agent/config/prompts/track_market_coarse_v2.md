将输入候选归并成适合联想 SMB 客户覆盖的略粗粒度制造业业务赛道。不是建立严格产品分类树。

优先减少同义重复、技术路线、档次、代际和应用变体。相关企业属于一个有意义的主营业务群时，可以覆盖相邻制造环节、整机与配套部件、产品与关键材料或相邻工序；不要求每个成员交付完全相同的产品。仅因为都使用 PC、服务器或都属于制造业，不足以合并。

一个局部业务群尽量合为一个赛道；确有明显不同的客户群时输出两个或少数几个。不要按技术或单一应用继续细分。比较包可能含多个无关业务群，分别处理，不强制把整个包合成一类。不照抄每条输入，不输出父赛道及其细分子赛道形成重复目录。

共同业务群应由一个稳定经营对象概括，不能仅靠智能、无人、新能源、先进等共同修饰词成立。若只能把不同对象用“及、与”罗列来凑出名称，应分别输出或保留独立，而不是硬拼成一个市场。这不禁止电池及关键材料等有实际共同经营基础的业务群。

输出 markets 列表，每项只包含 market_ref、name、offering_family、supplier_role、boundary、member_refs。每项至少引用两个真实候选。独立或无合并价值的候选不输出，程序保留。

允许混合候选同时支持两个不同输出，例如同时涉及整机和部件的候选支持整机市场与部件市场；其他非混合候选不要重复归属。输出间的区别必须在名称和一句 boundary 中清楚表达。不同 supplier_role 不混合。

名称可略粗，但需说明实际经营方向。boundary 不得给原候选擅自新增专属主营业务或生产工序，也不能把宽泛材料制造商特指成仅经营某个工序的厂商。原候选覆盖多个对象时，应在一个宽市场中覆盖这些对象，或用少数输出分别承接；不要只承接其中一部分，却在 boundary 中排除其余明确业务。不要求原候选每种技术都单独输出。

不得补充输入之外的产业方向。设施运营、建设施工和一般服务不转写为制造赛道；不负责删除原始候选。

若输入包含 previous_markets，统一这些重叠提议，允许一组多赛道，避免把同一业务群复制成不同措辞。

market_ref 使用 M1、M2 等不重复的短编号。只输出紧凑 JSON。
