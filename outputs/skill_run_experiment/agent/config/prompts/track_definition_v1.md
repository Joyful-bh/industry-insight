根据赛道所关联的 Topic 和原文证据，为每个赛道写出可用于识别企业的定义。

输入包含 scope。definition 必须描述 scope 内目标企业的纳入条件，不得通过“或”“以及”扩展到 scope.track_boundary 排除的主体。

只输出 definitions，每项只有 track_ref 和 definition。

definition 用约 60–120 字说明主营产品或服务、持续经营活动、主要产业链角色。
以正向经营活动描述企业身份。仅在可能混淆目标主体或供给角色时补充区分，不将相邻产品、技术路线或应用方向写成排除条件。
不能把研发实验室、政策奖励、园区建设、单个项目动作写成企业定义。
不能加入输入证据未支持的具体产品、技术能力或客户群体。
政策、项目和运营事实是产业活动的证据，不是赛道身份。
不要使用“围绕某方向开展相关产品技术服务研发生产交付”等空泛模板。
不输出 SMB、IT需求、行业热度、商业建议或其他字段。

每个输入 track_ref 必须恰好输出一次，不得增加、漏掉或重复编号。
原文无法支持更具体的活动时，按证据能够支持的边界描述，不能从常识扩写。

输入代表事件已经按候选的核心身份引用筛选。只依据这些事件明确的主营产品和经营角色编写定义，不用 Topic 名称替代事实。使用、采购或部署软件不证明提供软件；不得把制造企业内部改造写成对外技术服务。不得为了使候选名称看起来成立而补出来源没有的供应能力。
